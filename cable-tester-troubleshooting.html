Getting a cable test to run

The test needs a live wired link between two Macs. When it won't start, that link is almost always the reason — here's how to get it up.

What you need

All four, or the test can't run.

  • Two Apple Silicon Macs. M1 or newer on both ends. Intel Macs can't do this test.
  • The same version of PortScope open on the Cable Tester page on each Mac.
  • A Thunderbolt or USB4 cable. A charge-only cable or a plain USB-C cable will not link two Macs, no matter how many times you retry. Look for the ⚡ or a USB4 / 40Gbps marking near the plug.
  • A direct connection. Cable straight from a port on one Mac to a port on the other — not through a dock, hub, or adapter.

Start here

It doesn't matter which Mac hosts — the test measures both directions either way.

  1. On one Mac, click Host on this Mac.
  2. On the other, click Find a Host, then pick it from the list.
  3. Click Run Test and wait. A 4 GB run takes a minute or two.

The host doesn't appear in the list

The other Mac is advertising, but this one isn't seeing it.

  • Give it 10–20 seconds

    Discovery isn't instant. Leave both windows on the Cable Tester page while it searches.

  • Confirm the other Mac actually clicked Host on this Mac

    And that it's on the Cable Tester page, not another part of the app.

  • Try it the other way round

    Host from the Mac that was searching, search from the Mac that was hosting.

  • If PortScope says “Local Network access is off”

    On both Macs: open System Settings ▸ Privacy & Security, scroll to Local Network, switch PortScope on, then click Find a Host again.

  • Reseat the cable

    Push both ends in firmly. A loose plug can carry power (the Mac still charges) while carrying no data.

The host appears, but the test won't run

This is nearly always the wired link between the Macs, not PortScope. Work down the list in order — the early ones fix it most often.

  1. Swap roles

    Host from the other Mac and search from this one. If one Mac never works as the host, that Mac is blocking incoming connections — check its Firewall and Local Network privacy.

  2. Try different ports

    Move the cable to another USB-C port on each Mac. Ports on the same side of a laptop sometimes share one controller; the other side may behave differently.

  3. Rotate the connector

    Unplug, flip the USB-C plug 180°, plug back in — both ends. A worn or marginal plug can link in one orientation and not the other.

  4. Give the link time to come up

    After plugging in, macOS takes 10–30 seconds to bring the connection up. Open System Settings ▸ Network — Thunderbolt Bridge should appear and read Connected. If it doesn't, the cable isn't forming a Mac-to-Mac link.

  5. Turn Wi-Fi off on one Mac

    When both Macs share a Wi-Fi network, the test can get pulled toward it and stall. It only ever runs over the cable, so switching Wi-Fi off on one end costs you nothing.

  6. Unplug and reconnect the cable

    Both ends, wait five seconds, plug back in. Then wait for Thunderbolt Bridge to reconnect before retrying.

  7. Quit VPN and networking apps

    Tailscale, WireGuard, Internet Sharing and similar tools reroute traffic and can swallow the direct connection. Quit them on both Macs for the test.

  8. Keep both Macs awake and logged in

    The link drops when a Mac sleeps or sits at the login screen. Nudge the trackpad on the host if a run is long.

  9. Restart both Macs

    Clears a stuck Thunderbolt Bridge — the single most effective reset when nothing else has worked.

  10. Check Thunderbolt Bridge is set to DHCP

    In System Settings ▸ Network ▸ Thunderbolt Bridge ▸ Details ▸ TCP/IP, set Configure IPv4 to Using DHCP on both Macs. A leftover manual IP address on one side breaks the connection.

  11. Rule out the cable

    Borrow a cable you know is Thunderbolt — the one from a Thunderbolt dock, or an Apple Thunderbolt 4 Pro cable. If that one works and yours doesn't, you've found your answer: the cable can't sustain a Mac-to-Mac link.

What the messages mean

PortScope names the specific failure. Each points at a different fix.

The link dropped mid-test… the direct link is re-negotiating

The connection came up and then failed partway through. Reseat both ends, wait, and run it again. A cable that does this repeatedly is marginal — try another.

No wired route yet… hasn't finished coming up

Thunderbolt Bridge isn't connected. Wait for it, keep both Macs awake, then retry. Check System Settings ▸ Network.

Found it but it refused the connection

The host Mac is blocking incoming connections. Swap roles, or check that Mac's Firewall and Local Network privacy.

Found over Wi-Fi only — no wired link to this Mac yet

The other Mac was seen over Wi-Fi, but the cable link to it isn't up. Wait for Thunderbolt Bridge to connect — the test never runs over Wi-Fi.

What a good result looks like

Once it runs, this is how to read it.

  • The graph is a fairly flat line — Send and Receive tracking close together.
  • Consistency reads Steady or Minor fluctuation.
  • An Erratic result with a jagged graph is the signature of a marginal cable retraining under load. Retest with a known-good cable to compare.

“No device connected” can be misleading. The Thunderbolt section of System Information sometimes shows nothing even while the test runs fine — a USB4 link through certain ports doesn't register there. Trust the test result, not that screen.

Nothing leaves your Macs. The Cable Tester streams only between the two computers, straight over the cable being tested. No data goes to any server.
